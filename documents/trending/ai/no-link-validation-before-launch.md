# 无链接先验证：没有支付入口时的产品首发动作

没有小报童、表单或支付链接时，最容易出现两个坏选择：继续堆内容，或者假装已经可以发布。更好的选择是把首发拆成一次 **no-link validation**：只验证真实需求、问题原话和愿意继续沟通的人数，不提前收款，也不伪造可购买入口。

<!-- more -->

这张卡适合 AI 程序员做小产品、资料包、课程、咨询服务或自动化工具的早期验证。它的目标不是“上线”，而是在 30-60 分钟内拿到下一步决策需要的最小证据。

## 什么时候使用

满足任意一条，就先走 no-link validation：

- 还没有真实支付链接、留资表单或可公开试读页。
- 渠道账号、联系方式或发布时间没有被确认。
- 已经写了足够多内容，但没有真实用户问题、评论、私信或付费意向。
- Agent / 自动化流程一直在补文档，却没有任何外部反馈输入。

不要在这些状态下继续扩写第 8 篇、第 11 章或第 3 个版本。先把需求验证成可复核记录。

## 30 分钟动作

1. **选一个渠道**：只选一个你能手动发布和回复的渠道，例如朋友圈、社群、即刻、X、掘金或知乎。
2. **发问题征集帖**：核心句式是“我正在整理 X，想收 10 个真实问题；评论或私信关键词，我发你样刊 / 清单”。
3. **不放假链接**：没有真实链接就不要写“立即购买”“已上架”“点这里付款”。只写“私信领取样刊”或“回复关键词登记”。
4. **用私信收窄需求**：追问岗位、当前卡点、希望解决的具体问题、愿意付费的条件。
5. **记录原话和动作**：把曝光、评论、私信、样刊索取、早鸟意向、愿意留下联系方式的人数分开记。
6. **当天判断 Continue / Narrow / Stop**：不根据点赞数判断，只看是否出现可继续服务的证据。

## 可复制文案

```text
我在整理一份「[目标人群] 的 [具体问题]」资料，不先做大而全版本，想先收 10 个真实问题。

如果你最近卡在：
1. [痛点 A]
2. [痛点 B]
3. [痛点 C]

可以评论 / 私信「样刊」。我会发当前草稿，并追问 2 个问题：你现在最想解决哪一类问题？如果做成每周更新的小产品，你会因为什么愿意付费？

说明：现在还不是正式购买入口，不提前收款；这轮只验证真实需求和下一版方向。
```

## 私信追问脚本

```text
收到，我先发你当前样刊 / 清单。为了判断下一版该不该继续做，想追问 3 个很短的问题：

1. 你现在的角色 / 岗位是什么？
2. 这类问题里你最想先解决哪一个？
3. 如果它做成每周更新的资料 / 工具 / 服务，你愿意付费的前提是什么？
```

如果对方只回复“看看”，不要立刻推销。把它记为 `sample only`；只有出现具体问题、复述痛点、愿意留下联系方式、询问价格或请求后续更新，才算更强信号。

## 记录表

| 字段 | 记录方式 |
| --- | --- |
| 渠道 | 只写一个渠道，避免混合判断 |
| 发布时间 | 便于之后比较观察窗口 |
| 触达 / 浏览 | 没有数据就写 `unknown`，不要估算 |
| 评论数 | 只计真实问题或关键词回复 |
| 私信数 | 区分样刊索取、具体问题、价格询问 |
| 用户原话 | 保留 3-5 条可脱敏原话 |
| 早鸟 / 留资意向 | 只记明确愿意继续沟通的人 |
| 下一步 | `Continue` / `Narrow` / `Stop` |

## 判读规则

- **Continue**：至少 3 个具体问题，或 2 个愿意留下联系方式 / 询问价格的人；下一步补真实链接、样刊页或收款入口。
- **Narrow**：有人感兴趣但问题分散；下一步缩小人群、场景或承诺，例如只服务“准备 AI 项目面试的后端工程师”。
- **Stop**：只有点赞、泛泛支持或样刊围观；停止继续扩写内容，把这个方向封存到 backlog。

## 不做清单

- 不伪造购买链接、支付截图、报名人数或用户反馈。
- 不在没有授权的渠道自动发布。
- 不把“收藏 / 点赞”当作付费意向。
- 不为了显得忙而继续写长文、章节、Vol.011。
- 不提前收款；如果对方明确要付费，先补真实入口和退款 / 交付说明。

## 与 Agent 工作流的关系

Agent 可以准备文案、检查占位链接、生成记录模板和复盘草稿，但不能替你获得渠道授权、真实用户反馈或付款事实。一次 no-link validation 的完成标准是：有一条可复核发布记录、一份原话记录、一个 Continue / Narrow / Stop 决策，而不是又多了一篇计划文档。
