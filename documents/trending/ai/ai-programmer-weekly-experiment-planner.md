# AI 程序员每周收入实验规划器

当一条实验连续几轮拿不到真实渠道、样本或反馈时，不要继续扩写同一组文档。用这份规划器在每周开始时选择一个能本地验证、能交付、能沉淀资产的小实验。

<!-- more -->

## 先定义本周约束

先用四行写清现实条件，避免凭热情选择任务：

```text
本周可用时间：
可触达对象：自己 / 现有读者 / 开源维护者 / 朋友团队 / 付费客户
可交付边界：文档 / 脚本 / PR / 模板 / 服务样板 / 小工具
不能做的事：例如不能代发、不能接触私有代码、不能编造反馈
```

约束不是借口，而是选题过滤器。没有外部渠道时，优先做本地可验证的脚本、模板、教程或开源 PR；有真实对象时，优先交付对方能复核的下一步。

## 候选实验池

| 实验类型 | 一周内可交付物 | 本地验证方式 | 对外信号 | 适合何时选择 |
| --- | --- | --- | --- | --- |
| 工作流资产 | 一页操作清单、review 模板、失败复盘模板 | 用自己 repo 跑一遍，并记录命令、输入、输出 | 有人照着复现或提出具体问题 | 最近重复踩同一类流程坑 |
| 内容资产 | 一篇带真实命令和失败输出的教程 | 链接、命令、截图或构建结果可复核 | 收藏、提问、复现、引用 | 有清楚案例但暂时没有产品渠道 |
| 开源贡献 | 一个小 PR、测试补丁或文档修复 | 项目测试、lint、最小 demo 通过 | PR 被 review、合并或维护者要求后续修改 | 想证明可信交付能力 |
| 自动化工具 | 一个 CLI、脚本或检查器的最小版本 | `--help`、dry-run、fixture、smoke test 通过；文档改动可先跑 [AI 文档改动 Proof Checker](ai-doc-change-proof-checker.md) | 有人愿意在自己项目试用 | 同一检查动作重复出现三次以上 |
| 模板包 | prompt、清单、报告样板和示例输入 | 用一个脱敏 fixture 生成可读输出 | 有人复制、改写或请求定制 | 已有多个相似文档资产 |
| 服务 offer | 固定范围说明、接收表、样板报告 | 用只读样本演练一次交付链 | 对方愿意提供真实材料或预算 | 已有可信案例和触达渠道 |

## 选择规则

按下面顺序过滤，不要同时开多个实验：

1. **证据优先**：哪个候选已经有真实输入、失败输出、issue、PR、用户提问或重复自用场景？优先它。
2. **交付优先**：哪个候选能在 30-120 分钟内交付一个可复核结果？优先它。
3. **复用优先**：哪个结果下周还能被自己或别人再次使用？优先它。
4. **分发优先**：哪个结果可以自然发布到 README、博客、开源 PR、社群或书稿？优先它。
5. **停止优先**：如果一个候选需要编造用户、反馈或案例才显得完整，先放弃。

## 一周执行板

| 时间点 | 动作 | 产物 | 通过标准 | 不通过时 |
| --- | --- | --- | --- | --- |
| 周一 | 选一个实验，写清约束和停止条件 | 4 行实验说明 | 30 分钟内能解释给别人听 | 缩小到单点问题 |
| 周二-周三 | 做最小交付 | 文档、脚本、PR、模板或样板报告 | 有命令、截图、diff 或检查清单可复核 | 记录 `Next evidence needed` |
| 周四 | 验证和修正 | 真实运行结果或人工复核记录 | 至少发现一个需要改的点并修掉 | 停止包装，先补验证 |
| 周五 | 分发或归档 | README 入口、博客草稿、PR 链接、书稿卡片 | 有明确受众和下一步 CTA | 只归档为内部资产 |
| 周末 | 复盘 | `Continue / Narrow / Stop / Switch` 决策 | 决策基于证据而非感觉 | 下周换实验 |

## 本周实验卡片模板

```text
Experiment:
Audience:
Problem evidence:
Smallest deliverable:
Verification:
Distribution:
Stop condition:
Next evidence needed:
Decision: Continue / Narrow / Stop / Switch
```

填写时只写可验证事实：例如“`docs` 构建通过”“某个 PR 评论要求补测试”“脚本在 fixture 上输出 3 个缺失链接”。不要写“市场应该需要”“大家可能会喜欢”。

## 和资产飞轮衔接

完成一周实验后，把结果接回 [AI 程序员资产飞轮](ai-programmer-asset-flywheel.md)：

- 能复用的流程，整理成工作流或技能；
- 能解释判断力的过程，写成教程或书稿卡片；
- 能被别人反复使用的交付物，包装成模板包或工具；
- 有真实材料和预算信号的方向，再升级为服务 offer；
- 没有证据的方向，明确 `Stop / Switch`，不要靠继续写文档制造进展感。

## 自检

- 本周实验是否来自真实问题，而不是概念热词？
- 最小交付物是否能被命令、diff、fixture、PR 或人工检查复核？
- 是否有明确受众和分发入口？
- 是否写清了 `Next evidence needed` 和停止条件？
- 如果没有外部反馈，是否仍然留下了自己下周能复用的资产？
