# Agent Cron 工作日志资产提取器

定时 agent 的 notebook 不是成果仓库，而是线索仓库。每隔几轮要从工作日志里提取可复用资产：哪些判断已经重复出现，哪些验证命令值得固化，哪些停止条件应该变成模板、技能或书稿卡片。

<!-- more -->

## 什么时候使用

- `summaries/hermes/` 连续多轮都在重复同一类取舍、停止条件或验证命令。
- 本轮没有明确用户即时指令，需要从已有工作记录里选一个低风险小交付。
- 你担心继续写新文章会变成近重复扩写，但又不想只写 notebook。
- 某个项目、文档或技能目录已经有可提交的小入口，不需要接管未知 dirty path。

不适用：需要外部授权、真实客户样本、支付链接或发布渠道才能验证的任务。那些情况先写 `Next evidence needed`，不要把日志提取包装成市场验证。

## 三步提取法

### 1. 聚类：找重复判断，而不是找最长段落

从最近 3-7 条 notebook 里只摘这几类信号：

| 信号 | 说明 | 可能资产 |
| --- | --- | --- |
| 重复 stop rule | 多次因为同一边界停止 | skill reference / preflight card |
| 重复验证命令 | 多次手动跑同一检查 | script / checklist / docs proof |
| 重复交接句式 | 多次写同一类 handoff | template / receipt |
| 重复候选取舍 | 多次在同类任务中犹豫 | decision matrix |
| 重复收入约束 | 多次缺渠道、样本或链接 | offer preflight / evidence request |

不要按“哪段写得最好”选择资产；按“下次能少做一步判断”选择资产。

### 2. 压缩：把日志改成可执行入口

把候选日志压成下面的最小资产形状之一：

| 资产形状 | 最小内容 | 验证方式 |
| --- | --- | --- |
| 文档卡片 | 适用场景、步骤、停止条件、下一条命令 | markdown proof + catalog proof |
| 技能 reference | Decision gate、输入、输出、stop rule | grep/断言确认入口引用 |
| 脚本 | 单一检查、清晰 exit code、示例命令 | 单元测试或 fixture |
| 书稿卡片 | 场景、反例、原则、可复用句式 | 目录索引 + 人工可读 |
| 收入实验模板 | 渠道、CTA、证据字段、切换条件 | 一条真实发布/征集记录或明确阻塞 |

如果压缩后仍然只能写“建议继续观察”，说明它还不是资产；下一轮应回到真实证据收集。

### 3. 回写：让下一轮能直接接手

资产完成后，在 notebook 只记录四件事：

```text
Extracted signal: 从哪些重复判断/命令/停止条件提取
Asset created: 相对路径
Verification: 实际命令或人工复核标准
Next reuse point: 下一轮什么情况下先用它
```

回写时避免复制整篇新资产；notebook 负责交接，资产文件负责复用。

## 选择阈值

只有同时满足下面 3 条，才值得从日志提取资产：

1. **重复度**：同一信号至少出现 2 次，或本次明显会在未来重复。
2. **可验证**：能用命令、断言、目录索引或人工 checklist 证明资产存在且可用。
3. **可接力**：下一轮 agent 能在 2 分钟内知道什么时候使用它。

不满足时，不要硬写文档；改为在 notebook 中记录 `Narrow`，并把下一条命令写成真实信息收集动作。

## 与 cron 交付预算衔接

先用 [Agent Cron 交付预算卡](agent-cron-delivery-budget-card.md) 判断本轮有没有 15-45 分钟可交付小块；如果候选小块来自历史 notebook，再用本页完成提取。

建议顺序：

1. 快照当前 dirty path，确认不接管未知改动。
2. 读最近 1-3 条 handoff，找重复 stop rule 或验证命令。
3. 用“选择阈值”判断是否值得资产化。
4. 只新建或修改本轮拥有的少量文件。
5. 跑 scoped proof，不用全仓构建冒充验证。
6. notebook 记录提取信号、资产路径、验证结果和下次复用点。

## Stop rule

出现下面任一情况，停止资产提取：

- 只是把上一轮总结改写成另一篇总结，没有减少下一轮决策成本。
- 资产需要引用未授权客户、私有仓库、真实支付链接或不可公开截图。
- 需要修改的入口文件已有未知冲突，且没有新文件替代方案。
- 只能通过想象未来读者需求来证明价值，没有重复信号或当前任务支撑。

停止时写：`Decision: Stop extracting; next evidence needed: <具体证据或命令>`。
